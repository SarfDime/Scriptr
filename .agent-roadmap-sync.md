# Roadmap Sync and Progress Agent

## Purpose
This agent automatically maintains the roadmap and documentation in sync with actual implementation progress. It bridges the gap between engineering work and the written product specification.

## Trigger Points

### 1. Commit Message Pattern
When a commit includes `[ROADMAP: Phase X - Feature Name]`, this agent:
- Parses the phase and feature name
- Updates the roadmap.md progress section
- Regenerates workspace AGENTS.md files
- Updates CLAUDE.md with fresh context

### 2. Manual Invocation
A developer can trigger the agent in a conversation with:
```
@agent:roadmap-sync update phase:2 feature:"Backend API structure" status:"in-progress"
```

### 3. Scheduled Check (Future)
Could run on-demand to scan for completed work and prompt updates.

## Implementation Rules

### Status Markers
- ✅ Completed - all subtasks done, validated, tested
- ✏️ In Progress - actively being worked on
- 🔲 Planned - approved but not started
- 🚫 Blocked - blocked, reason documented

### Update Format
When updating a phase in roadmap.md:

```markdown
### Phase N: Feature Area [Status]
Last updated: YYYY-MM-DD

1. Subtask one [Status]
   - Implementation notes or blocker reason
2. Subtask two [Status]
```

### Workspace-Specific Updates

#### AGENTS.md (Monorepo Root)
Add or update a section for the current phase:

```markdown
## Current Phase: Phase N - Feature Area

Focus: [Brief description of current work]
Key Files:
- [specific files being modified]

Dependencies:
- Phase X-1 must be complete before this phase starts
- Schema must include field Y

Patterns:
- Use [pattern name] for [feature type]
- See [file.ts] for reference implementation
```

#### Workspace CLAUDE.md (next/, sanity/, hono/)
Add practical implementation notes:

```markdown
## Current Focus: Phase N - Feature Area

Working on: [specific feature]
Key constraints: [database field requirements, API contracts, etc.]
Reference implementations: [point to similar existing code]
Next steps: [what blocks the next phase]
```

## Workflow Example

### Step 1: Developer commits work
```bash
git commit -m "[ROADMAP: Phase 2 - ID-based routes] Build professor/[id] page

- Implemented dynamic professor page component
- Merges DB identity with Sanity metadata
- Added loading, error, and not-found states
- Tests pass for all edge cases"
```

### Step 2: Agent detects and parses
```
Detected: Phase 2, Feature "ID-based routes"
Status: in-progress (inferred from commit message verb "Implemented")
```

### Step 3: Agent updates roadmap.md
```markdown
### Phase 2: Core content and discovery [✏️ In Progress]
- Build dynamic ID-based pages for universities, faculties, subjects, and professors. [✏️]
  - Professor page implemented (2026-09-06)
  - Faculty, subject, university pages pending
```

### Step 4: Agent updates AGENTS.md
```markdown
## Current Phase: Phase 2 - Core content and discovery

Focus: ID-based routes for academic entities and script discovery
Key Files:
- next/app/professor/[id]/page.tsx (reference)
- next/app/subject/[id]/page.tsx (next)
- hono/src/routes/academic-entities.ts (backend)

Dependencies:
- Phase 1 schemas must be deployed to Sanity
- DB sync endpoints needed for each entity type

Patterns:
- Academic pages merge DB row + Sanity document
- Use `mergeAcademicEntity()` helper from lib/entity-merge.ts
- Include loading/error states for all fetch operations
```

### Step 5: Developer sees updated context on next pull
The AGENTS.md now highlights the current work, patterns, and blockers.

## Implementation Checklist for Agents

When implementing this pattern in your workspace:

1. **Read the roadmap** before starting a phase
2. **Commit with roadmap tags** to maintain sync
3. **Check AGENTS.md** for current phase patterns
4. **Check workspace CLAUDE.md** for local implementation notes
5. **Update progress** whenever a subtask completes

## Future Integration Points

### Pre-commit Hook
Could validate that commits touching certain files include a roadmap tag:
```bash
# .git/hooks/pre-commit
if git diff --cached --name-only | grep -qE "(src/|sanity/|next/app/)"; then
  if ! git diff --cached | grep -q "\[ROADMAP:"; then
    echo "Error: commits modifying source files must include [ROADMAP: ...] tag"
    exit 1
  fi
fi
```

### GitHub Action
Could post progress updates to a project board or Slack:
```yaml
on: push
jobs:
  roadmap-sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Parse roadmap updates
        run: |
          # Extract [ROADMAP: ...] from commit messages
          # Update roadmap.md
          # Post summary to Slack
```

### IDE Integration
Could highlight roadmap references in code:
- Flag functions implementing a roadmap item
- Suggest CLAUDE.md patterns for current work
- Warn if code touches areas outside current phase

## Sync Failures & Manual Recovery

If the agent fails to update something:

1. **Roadmap is out of sync**: Manually update roadmap.md section 10
2. **AGENTS.md is stale**: Manually update the "Current Phase" section
3. **CLAUDE.md is unclear**: Add implementation notes directly to the file

Then commit with `[ROADMAP-SYNC: manual update] <reason>`
