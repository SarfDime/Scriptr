# Commit Agent for Roadmap Sync

## Overview
This agent monitors commits and automatically updates the roadmap, documentation, and agent configurations based on progress.

## Trigger Pattern
Include a roadmap reference in your commit message:

```
[ROADMAP: Phase X - Feature Name] Commit message description

Details about what was implemented.
```

### Examples
```
[ROADMAP: Phase 1 - Sanity schema] Add academic entity document types

Implement university, faculty, subject, and professor schemas with validation rules.
Closes schema foundation task.
```

```
[ROADMAP: Phase 2 - ID-based routes] Build professor/[id] page

Generate dynamic page from Sanity + DB merge. Add loading and error states.
```

```
[ROADMAP: Phase 4 - Create script flow] Implement subject selection and auto-population

Scripts now auto-resolve professor, faculty, university from subject. Validation added.
```

## What the Agent Does

When a commit with `[ROADMAP: ...]` is detected:

1. **Parse the roadmap section** from the message (Phase X, Feature Name)
2. **Update roadmap.md** status for that feature to ✏️ In Progress
3. **Regenerate AGENTS.md files** with the next priority/phase highlighted
4. **Update workspace CLAUDE.md** with new implementation focus
5. **Log progress** in the roadmap under a "## 11. Progress and Status" section

## Expected Format

### Commit Message Structure
```
[ROADMAP: Phase N - Feature Name] One-line summary

Paragraph or bullet details:
- What was implemented
- Key decisions made
- Tests added or validation completed
```

### Roadmap Section Format
Each Phase will have a status line:
```
### Phase N: Feature Area [Status]

Status markers:
- ✅ Complete
- ✏️ In Progress  
- 🔲 Planned
- 🚫 Blocked (reason)
```

## Files Updated by the Agent

1. **roadmap.md**
   - Updates phase/feature status
   - Adds timestamp of last progress update
   - Notes key implementation decisions

2. **AGENTS.md** (root)
   - Updates next-phase guidance
   - Highlights blocking dependencies
   - Notes schema/sync requirements

3. **next/CLAUDE.md** or workspace-specific CLAUDE.md
   - Adds implementation hints for current phase
   - Notes component patterns established
   - Documents any new utilities or hooks

4. **sanity/CLAUDE.md** (if exists)
   - Updates schema patterns and completed documents
   - Notes sync endpoints implemented

## Manual Invocation

To manually trigger a roadmap update without a commit:

```bash
npm run roadmap:update -- --phase=2 --feature="ID-based routes" --status="in-progress"
```

(This script should be added to package.json in the future if manual updates are common.)

## Example Workflow

1. Developer works on Phase 2 backend routes
2. Commits with `[ROADMAP: Phase 2 - Backend API structure]`
3. Agent detects commit
4. Agent updates roadmap.md to mark Phase 2 as ✏️ In Progress
5. Agent regenerates AGENTS.md to emphasize Phase 2 patterns and next steps
6. Agent adds a status note with the commit date and feature summary
7. Next developer sees the updated roadmap and CLAUDE.md with fresh context
