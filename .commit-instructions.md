# Commit Message Generation Guide

When generating commit messages, **always include the roadmap phase tag** if the commit advances a roadmap phase or completes tasks within a phase. This enables automatic roadmap progress tracking.

## Pattern

```
[ROADMAP: Phase X - Feature Name] Commit summary

- Detailed task 1
- Detailed task 2
- Detailed task 3
```

## When to use the roadmap tag

- ✅ Use when: Implementing a feature listed in a roadmap phase
- ✅ Use when: Completing subtasks that move a phase forward
- ✅ Use when: Work spans multiple files/components but serves one phase goal
- ❌ Skip when: Fixing typos, formatting, or unrelated refactors
- ❌ Skip when: Work doesn't correspond to a roadmap phase (e.g., dependency updates)

## Phase reference

- **Phase 1**: Database foundation and backend API
- **Phase 2**: Sanity CMS setup and academic entity management
- **Phase 3**: Core content and discovery
- **Phase 4**: User actions and uploads
- **Phase 5**: Profile and onboarding
- **Phase 6**: Moderation and admin tools
- **Phase 7**: Polish and iteration

## Examples

### Phase 1: Database work
```
[ROADMAP: Phase 1 - Database foundation] Create users and scripts tables

- Implement users table with auth fields and roles
- Implement scripts table with metadata and relationships
- Add constraints and indexes for data integrity
- Validate schema against v1 requirements
```

### Phase 2: Sanity work
```
[ROADMAP: Phase 2 - Sanity setup] Create academic entity document types

- Define university document type with reference fields
- Define professor document type with bio and image
- Add validation for required fields
- Set up Sanity Studio structure and desk organization
```

### Phase 3: Frontend work
```
[ROADMAP: Phase 3 - Core discovery] Build professor page with ID-based routing

- Implement professor/[id] dynamic page component
- Merge DB identity record with Sanity metadata
- Add loading and error states
- Integrate with script listing
```

## Benefits

- Automatic progress tracking via commit agent
- Roadmap.md stays in sync with actual implementation
- AGENTS.md and workspace CLAUDE.md update automatically
- Clear audit trail of which phase each commit belongs to
- No manual status updates needed

## Implementation trigger

When you commit with the `[ROADMAP: Phase X - Feature Name]` tag, the roadmap sync agent automatically:
1. Parses the commit message
2. Updates roadmap.md with progress markers
3. Regenerates AGENTS.md with current phase focus
4. Updates workspace CLAUDE.md with implementation context
